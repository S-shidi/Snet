# Snet v1.2.0

## Breaking Change

This release introduces **network-level SnetServ binding**. A network now
belongs to one coordination server (`SnetServURL`), and clients route requests
for each network to that server independently.

Old clients **v1.1.16 and earlier** only understand a single global SnetServ and
cannot join a network hosted on another SnetServ. They may also treat an invite
for another server as an attempt to switch their global server.

## Upgrade Order

Upgrade in this order:

1. Upgrade every SnetServ / coordination server.
2. Upgrade every client (macOS, Windows, Android, Docker/NAS) to v1.2.0.
3. Only then distribute invite links for networks on secondary SnetServs.

Do not enable cross-SnetServ invites until all intended clients are on v1.2.0.

## New Behavior

- `Network` records carry `snetServUrl` / `snetServId`.
- `/ctl/status.networks` includes `snetServUrl` for every network.
- The client create-network dialog accepts an optional coordination server.
- Invite links bind the network's own SnetServ in the encrypted `s=` field.
- NAT mappings use the network's SnetServ to choose the local source interface.
- The owner limit is scoped per SnetServ: one owner-created network per device
  per SnetServ. A device can create on another SnetServ, which is intentional
  for federation testing but is not a substitute for a global quota.

## Known Limits

- `admin-server` currently manages a single SnetServ. Multi-SnetServ federation
  management is planned for v1.3.0.
- The second test SnetServ uses the existing `snet.uizhi.eu.org` certificate on
  port 8097. Production deployments should provide an appropriate TLS hostname
  and certificate for every SnetServ.
- Existing legacy fallback helpers are retained for compatibility. Production
  network paths use per-network routing.

## Server Upgrade

`cmd/server` remains as a compatibility entry point. New deployments may use
the split `cmd/snetserv` and `cmd/admin-server` entries. Set
`SNETSERV_PUBLIC_URL` (or `-public-url`) for every SnetServ so invite links are
generated with the correct URL.
