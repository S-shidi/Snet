# SNET v1.2.0

Relay v2 and direct-path upgrade. Relay v2 is **disabled by default**; the
legacy relay pool remains active until the coordination server is explicitly
enabled with matching `SNET_RELAY_V2_ENDPOINT` / `SNET_RELAY_SECRET`.

## Added

- Standalone Relay v2 service (`snet-relay`) with HMAC-signed tickets, per-node
  sessions, precise node-ID forwarding, `/healthz`, and Prometheus metrics.
- Relay-assisted direct path upgrade: ephemeral UDP mapping registration,
  peer lookup, direct probe/ping, per-peer path status, and automatic relay
  fallback after loss.
- `/ctl/status.relayPath.peerDirect` for per-peer `direct|probing|discovering`
  visibility.
- `scripts/rollout-vps.sh` optional relay deployment and synchronized
  `SNET_RELAY_*` configuration.

## Changed

- WireGuard MTU is now `1320` on Go and Android.
- Android injects only joined-network CIDRs plus peer `allowedSubnets`, not a
  blanket `10.0.0.0/8`; `excludeRoute` requires API 33+.
- VPS deployment is server-only; member clients run on NAS, SDserver, desktop,
  and Android.

## Fixed

- Windows MTU documentation and configuration now consistently use `1320`.
- Relay session lifecycle rejects idle/expired direct and data frames.

## Compatibility

- Product version: `1.2.0`
- Coordination `APIVersion`: `1`
- With Relay v2 disabled, `1.2.0` clients retain legacy relay/direct behavior.
- **Relay v2 is a flag day when enabled**: upgraded clients use only Relay v2
  and cannot exchange traffic with old clients in the same network. Upgrade all
  clients before enabling the server endpoint. To roll back, clear
  `SNET_RELAY_V2_ENDPOINT` and restart the coordination server.

## Upgrade order

1. Coordination server (`snet-server`) with Relay v2 disabled.
2. NAS, SDserver, desktop, Android, and Windows clients.
3. Verify all members report `1.2.0`.
4. Configure matching `SNET_RELAY_V2_ENDPOINT` and `SNET_RELAY_SECRET` on both
   server and relay, then verify direct/relay fallback per peer.

## Known issues

- Windows NSIS and signed Android release builds were not rebuilt locally.
- Real-device Relay v2 direct/fallback behavior is not yet verified.
- The previous VPS→SDserver relay-loss regression still requires data-plane
  revalidation after clients are upgraded.
