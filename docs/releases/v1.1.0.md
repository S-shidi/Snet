# SNET v1.1.0

> Draft release notes. Verify all platform builds and update this file before
> tagging `v1.1.0`.

## Added

- Automatic NAT port mapping via UPnP-IGD, NAT-PMP, and PCP, with a runtime
  toggle and per-network status.
- Android Compose client improvements: QR join, approval workflow, auth-expiry
  guidance, dynamic peer subnet routing, and VPN restart on route changes.
- Versioned release pipeline with build metadata, binary `-version` output,
  `/healthz` build fields, and `/ctl/status` client version.
- Windows installer now bundles `snetd.exe`, `wintun.dll`, and the Wintun
  license; CI downloads and checksum-verifies Wintun 0.14.1.

## Changed

- All components now use the product version `1.1.0`; Android `versionCode` is
  `10100`.
- Docker images are version-tagged and carry OCI version/revision/created labels.
- VPS, macOS, and NAS rollout scripts verify deployed versions and keep backups.

## Fixed

- Docker Web `/ctl/*` authentication now requires a valid Web session.
- Joined members can see `allowedSubnets`; owner-only fields remain hidden.
- Relay fan-out and shared-egress attribution across multi-node networks.
- Windows NSIS installer no longer omits the daemon or Wintun runtime.

## Compatibility

- Product version: `1.1.0`
- Coordination `APIVersion`: `1`
- Existing `APIVersion` 1 clients remain compatible with this server.

## Upgrade order

1. Coordination server (`snet-server`).
2. SDserver / NAS clients.
3. VPS client container.
4. Desktop, Android, and Windows clients.

## Known issues

- Windows installer is not Authenticode-signed; SmartScreen may warn.
- macOS desktop app packaging is not part of the automated release yet.
- Android release APK requires signing secrets in CI.
- Windows installer and Android real-device installation still require manual
  verification before tagging.
