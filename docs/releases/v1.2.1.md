# Snet v1.2.1

## Highlights

- Multi-network clients now handle local WireGuard UDP port collisions: stale
  or duplicate ports are re-picked automatically, and a failed bind retries on
  a different port instead of repeatedly trying the same one.
- The Windows and macOS trays list every network directly with its local IP and
  a status dot. Route rows use the same arrow/cross state symbols as the subnet
  route panel.
- The client startup screen now shows a centered “starting / loading networks”
  state instead of a misleading empty-network create/join prompt.
- The member card’s device ID is aligned with the other fields and no longer
  shows a hover box.
- The admin invite link now always comes from snetserv using the network’s
  `snetServUrl` (falling back to the official server), never the admin request
  host.
- The configurable global default SnetServ has been removed; every network
  stores its own coordination server.
- Fixed a server race where a node heartbeat write could restore a deleted
  node row.

## Upgrade Order

1. Upgrade every SnetServ / coordination server to v1.2.1.
2. Upgrade clients: macOS, Windows, Android, Docker/NAS.
3. Distribute cross-SnetServ invite links only after all intended clients are
   on v1.2.1 or later.

## Compatibility

- Clients v1.1.16 and earlier cannot join a network hosted by a different
  SnetServ. Keep all participants on v1.2.1 or later before distributing
  cross-server invites.
- The global `serverAddr` / `defaultSnetServUrl` config keys are ignored and
  removed on load. Existing networks without a binding use the official
  default; new network creation or joining carries the per-network server.
- `admin-server` still manages one SnetServ. Multi-SnetServ admin federation
  remains planned for v1.3.

## Deployment

- Docker images: `snet-client:v1.2.1`, `snet-server:v1.2.1`,
  `snet-relay:v1.2.1`, plus `latest`.
- GitHub assets: macOS DMG, Windows installer/portable ZIP and Android APK.
